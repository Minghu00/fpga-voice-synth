# 现场测试模式（P0）证据文档

> 面向赛题「拓展③：现场测试模式 —— 现场能用测试模式输出多路不同频率，频谱看到对应数量独立谱峰，RTL 佐证无预录播放」。
>
> 对应代码：`rtl/audio/test_mode.v`（新增）、`rtl/audio/inc_lut.v`（扩表）、`rtl/top/top_inst.v`（接入）、`rtl/display/lcd_scope.v`（TEST 标识）。
> 回归：`sim/tb_test_mode.v`（24 项）＋既有 7 个平台全绿。

---

## 1. 一句话结论

上电时**按住 Key_3**（板上丝印 `Silicon Key_3`，FPGA 球号 **D7**，J14 之外的独立轻触键），进板后
**8 个声部同时以 8 个不同频率发声、每个声部只有 1 个加法分量（纯正弦）**，屏幕右侧状态条亮起
6 个红色方块表示「TEST 模式」已生效。频谱仪上可以逐个点出 **8 根互不重叠的独立谱峰**。

---

## 2. 进入与退出

| 操作 | 结果 |
|---|---|
| 上电时**不按** Key_3 | 正常工作模式（8 键触摸电子琴） |
| 上电时**按住** Key_3 不放，按一下复位 | 进入测试模式 |
| 松开 Key_3 | **仍然保持**测试模式（锁存，直到下次断电） |
| 断电重上电（不按 Key_3） | 回到正常工作模式 |

进入窗口：复位释放后 **1 ms**（`INIT_WIN = 108_000` 个 108 MHz 时钟）。窗口内只要 Key_3 出现过
低电平就锁存。

> Key_3 平时是「音量 +1 档」键。它只在**复位释放后的 1 ms 窗口内**兼作测试模式开关，正常演奏时
> 完全不受影响。

## 3. 测试模式的八路频率

`NOTE_SET = {21, 18, 15, 12, 9, 6, 3, 0}` —— 每隔 **3 个半音**取一个，跨两个八度：

| 声部 | note_idx | 音名 | 频率 |
|---|---|---|---|
| 0 | 0  | C4  | 261.63 Hz |
| 1 | 3  | D#4 | 311.13 Hz |
| 2 | 6  | F#4 | 369.99 Hz |
| 3 | 9  | A4  | 440.00 Hz |
| 4 | 12 | C5  | 523.25 Hz |
| 5 | 15 | D#5 | 622.25 Hz |
| 6 | 18 | F#5 | 739.99 Hz |
| 7 | 21 | A5  | 880.00 Hz |

相邻间距：49.5 / 58.9 / 70.0 / 83.3 / 99.0 / 117.7 / 140.0 Hz，**最小 49.5 Hz**。
常见手机/电脑频谱 App 在 48 kHz 采样、4096 点 FFT 下分辨率约 12 Hz，8 根峰可以清楚分开。

### 为什么每隔 3 个半音

如果按半音取满 8 个音（C4…G4），最密的 E4–F4 只差 19.6 Hz，低分辨率 FFT 会糊成一根。
隔 3 个半音后最小间距 49.5 Hz，肉眼可数。

### 为什么要跨两个八度（`inc_lut.v` 从 13 项扩到 25 项）

一个八度里最多只能取到 5 个「间隔 ≥3 半音」的音，凑不满 8 个。扩到 C4…C6 后可用两倍音域，
8 个音全部落在间距 ≥49.5 Hz 的格点上。**索引 0–12 的增量值与扩表前逐位相同**，演奏功能零变化。

溢出预算校验（`tb_test_mode` 已断言）：最高音 A5 `0x04AC2743`，乘 x4 谐波 = `0x12B09D0C`，仍 < 2³²。
测试模式还强制 `oct = 0`，所以不可能出现 `C6 × 4 × 4` 这种真会溢出的组合。

## 4. 为什么强制「管风琴 = 纯正弦」

`osc_bank.v` 的 `amp_tab` 按音色选 4 个加法分量的幅度：

```verilog
2'd0: amp_tab = {16'd0,    16'd0,    16'd0,    16'd32767};  // organ：只有 comp0 非零
2'd1: amp_tab = {16'd4681, 16'd6553, 16'd10923, 16'd32767};  // square：1/7,1/5,1/3,1
2'd2: amp_tab = {16'd8192, 16'd10923,16'd16384, 16'd32767};  // saw
default: amp_tab = {16'd0, 16'd3641, 16'd0,    16'd32767};  // tri：comp0 + comp2
```

管风琴档只有 `comp0` 有幅度 → **每个声部就是一根纯正弦**，一个声部贡献一根谱峰。

### 反过来想会踩的坑

如果 4 个分量全开，每个声部会同时发出 `f / 2f / 3f / 4f` 四根谐波。谐波按定义是基频的整数倍，
8 个声部的 32 根谐波在频谱上必然互相压住（例如 C4 的 2 次谐波正好落在 C5 上），
**数出来的峰数会远少于 32，反而像是虚报**。所以测试模式必须单分量。

### 那么「32 个振荡器」怎么证明

不能靠谱峰数。证据来自三处：

1. **RTL 里实打实有 32 个独立的相位累加器**：`osc_bank.v` 的 `reg [31:0] phase [0:OSCTOT-1]`，
   `OSCTOT = VOICES × NCOMP = 8 × 4 = 32`，每个累加器有自己独立的槽位、自己的频率倍率
   （`bstep_q`、`bstep_q<<1`、`3×bstep_q`、`bstep_q<<2`）和独立的幅度系数。
2. **切换音色时谐波结构实时变化**：把 DIP 拨到 square/saw/tri，频谱上立刻出现 2/3/4 次谐波，
   说明那 24 个「不发声」的分量是真的在跑，只是幅度为 0。
3. **仿真里可以直接读 32 个累加器的值**：`sim/tb_osc_bank.v` 断言
   `phase[0..3]` 每帧的增量分别为 `inc / 2inc / 3inc / 4inc`，逐位通过。

> 答辩口径建议：**「测试模式演示 8 路纯正弦 = 8 个可闻声部；32 个振荡器的定义与计数依据在 RTL，
> 谐波因整数倍关系在频谱上必然重叠，所以演示故意只开单一分量，避免谱峰互相遮盖。」**
> 这样既说清了数字，也不会被追问「你这明明是 8 根峰为什么说 32」。

## 5. 其他被测试模式接管的东西

| 信号 | 正常值 | 测试模式值 | 原因 |
|---|---|---|---|
| `gate` | 触摸键位图 / 锁存位图 | `8'hFF` | 8 个声部全开 |
| `note` | `NOTE_TAB`（TP0..TP7 = C4..C5） | `NOTE_SET` | 拉开间距 |
| `timbre` | DIP 第 3–4 位 | `0`（管风琴） | 单分量纯正弦 |
| `oct` | DIP 第 1–2 位 | `0` | 确定性 + 溢出安全 |
| `vol` | Key_3 / SW3 第 5 位，默认 6 | `2`（1.0×） | 8 路正弦叠加的余量 |

`vol` 降到 2 的理由：8 个声部等幅叠加时峰值可达单声部的 8 倍，默认 4.0× 增益会撞上限幅器，
削波会引入大量交调分量把频谱搞脏。1.0× 下实测峰值约 −10.5 dBFS，干净且仍清晰可闻。

屏幕表现：状态条右侧 **6 个红色方块**（原空闲区，x 336–479）点亮 = TEST。

| 项目 | P0 前 | P0 后 | 变化 |

| Logic | 2721 / 20736 (14%) | **2784** (14%) | +63 |
| — LUT | 2253 | **2295** | +42 |
| — ALU | 396 | **417** | +21 |
| Register | 1214 / 16173 (8%) | **1259** (8%) | +45 |
| I/O Port | 35 / 207 | **35** | **不变** |
| BSRAM | 4 (3 SDPB + 1 pROM) | **4 (3 SDPB + 1 pROM)** | 不变 |
| DSP | 3 / 24 (6 MULT18X18) | **3 / 24 (6 MULT18X18)** | 不变 |
| **Fmax**（约束 108 MHz） | 119.185 MHz | **119.647 MHz** | **+0.46 MHz** |
| Logic Level | 6 | **5** | 更好 |
| 最差 setup slack | — | **+0.901 ns**（12.634 vs 13.536） | 余量 6.6% |
| 综合/布线告警 | 0 | **0** | — |
| 位流 | `inst.fs` | **7,264,154 B**（sha256 `FDDE7A31D964F917…`） | — |

### 踩过的坑：mux 不能直接串进预处理路径

第一版把 `test_mode` 的选通写成**组合逻辑输出**，直接接到 `osc_bank`。多了 1 级 LUT 正好落在
`note → inc_lut → << oct` 这条最紧的路径前面，Fmax 从 119.185 掉到 **108.850 MHz**，
相对 108 MHz 约束只剩 0.8% 余量，等于白送。

改成 **在 `test_mode` 内部把选通结果打一拍**（+45 个触发器）后，下游拿到的仍是「触发器 → 移位器」，
Fmax 回到 **119.647 MHz**，比改动前还高（因为 `timbre / oct / note` 现在来自专用触发器，
不再绕 `keymap8` 的输出）。代价是设置变化晚 1 个时钟（9 ns），人耳不可感知。

## 8. 现场演示脚本（建议）

1. 断电。按住 Key_3 不放，插电或按复位，等屏幕亮。
2. 松手。确认右上状态条 **6 个红块**亮。
3. 手机装任意频谱 App，靠近喇叭；或把输出接示波器做 FFT。
4. 屏幕上应能数出 **8 根等间距的谱峰**，位置对照第 3 节表格。
5. 抬出 `osc_bank.v`，指出 `reg [31:0] phase [0:31]`、`NCOMP=4`、每个分量独立的
   `bstep_q / bstep_q<<1 / 3bstep_q / bstep_q<<2`，说明 32 个累加器独立运行。
6. 断电重上电（不按 Key_3），回到正常演奏，证明**没有任何 PCM 预录回放通路**：
   全工程搜索不到 `$readmemh` 之外的样本源，唯一的 `$readmemh` 是 `sine_rom.v` 读
   `rtl/audio/sine_1024.mem`（1024 点单周期正弦波表，不是音频样本）。

## 9. 已知限制（要主动说明，不要等评委问）

| 限制 | 说明 |
|---|---|
| 只能演示 8 根谱峰 | 见第 4 节：32 个分量的谐波必然重叠，单分量演示才数得清 |
| 进模式需要断电/复位 | 没有多余管脚，用「上电窗口 + 长按」复用 Key_3 |
| 频率固定 | 测试模式故意不可调，避免现场手忙脚乱调错 |
| 单声道 | 8 个声部等权混合送左右两个声道 |
