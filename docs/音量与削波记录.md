# 音量与削波记录 —— 「锁存模式同时多音时声音颤抖」的诊断与修复

## 1. 现象

用户反馈（m09125 原文）：

> 为什么开启锁存模式，同时开始多音时，声音不正常，听起来像颤抖

单音完全正常，一叠加到四五个音就开始"抖"。不是破音那种沙哑，是一种低频的、周期性的起伏，
听起来像有人在快速拧音量钮。

## 2. 根因：信号链被钉死在"刚好满刻度"上，没有余量

不是某一个参数写错，是三个设计决定叠在一起，任何一个单独看都合理：

### 2.1 `mixer16` 已经把 8 个声部归一化到满刻度

```verilog
out <= sat16(accum >>> MIX_SHIFT);   // MIX_SHIFT = 3 for VOICES = 8
```

`8 × 32767 >> 3 = 32767`。也就是说**8 个声部同时满幅时，混音输出正好是满刻度**。
这是当初为了「频谱页要干净的谱峰、不允许削波」而特意选的，但它同时意味着：
**只要单个声部不满幅，后面就没有任何余量可用。**

### 2.2 `audio_out` 上电默认是 4.0 倍

```verilog
vol_idx <= 4'd6;                      // gain_q = 1024 = Q8 的 4.0x
```

`vol_idx = 6` 对应 Q8 的 1024，即 `×4`。单声部 2047 counts 经放大后是 **8188**（−12 dBFS），
一个音听起来很合适 —— 但混音已经被归一化过了，再乘 4 就是把 8 声部的余量全吃掉。

### 2.3 音量键只能加，不能减

修复前 `vol_idx` 的范围是 **6..10**（4.0×..16×）。用户能做的只有"更大声"，
**没有任何办法把音量调回 1.0×**。所以现场一旦叠音削波，操作者是束手无策的。

## 3. 削波时的头 room 表（默认 `vol_idx = 6`，即 ×4）

单声部混音峰值 2047，`audio_out` 输出 `x = 2047 × 4 × N`：

| 同时按下的音数 N | 进限幅器前 x | 修复后输出（软拐点 24576） | 修复前（硬削顶） |
|---:|---:|---:|---|
| 1 | 8188 | 8188 | 8188 |
| 2 | 16376 | 16376 | 16376 |
| 3 | 24564 | 24564 | 24564 |
| 4 | 32752 | 25598 | **32767（削）** |
| 5 | 40940 | 26621 | **32767（削）** |
| 6 | 49128 | 27662 | **32767（削）** |
| 7 | 57316 | 28703 | **32767（削）** |
| 8 | 65504 | 29694 | **32767（削）** |

削顶之后输出变成方波。**方波的谐波与各声部的基频做互调，产生 |f1−f2| 这种低频差拍分量** ——
这就是听到的"颤抖"。差拍频率落在 5~40 Hz，正是人耳最敏感的那种"忽强忽弱"。

> 声学上这是纯互调失真（IMD），不是颤音（vibrato）：颤音是基频在动，互调是出现新的低频分量。

## 4. 修复

### 4.1 软限幅器（`rtl/audio/audio_out.v`）

不再硬削到 ±32767，改成两段折线：

```verilog
localparam signed [30:0] KNEE = 30'sd24576;   // 0.75 满刻度

function signed [15:0] soft;
    input signed [30:0] x;
    reg   signed [30:0] ax, y;
    begin
        ax = x[30] ? -x : x;                  // 先取绝对值
        if (ax <= KNEE) y = ax;               // 1 : 1
        else            y = KNEE + ((ax - KNEE) >>> 3);   // 斜率 1/8
        if (y > 30'sd32767) y = 30'sd32767;
        soft = x[30] ? -y : y;                // 再还原符号
    end
endfunction
```

要点：

- **拐点放在 3/4 满刻度**。低于拐点完全线性 —— 单音、双音、三音的听感和测量值都一个 counts 不差，
  所以 `tb_audio_out` 里 1.0×/4.0×/0.5× 那几项期望值全不用改。
- **斜率 1/8**。8 个音叠加时压到 29694，仍然比拐点高 5000 counts，
  也就是"挤进去"了但还能分辨音数，不会像硬削那样全部拍平到同一个值。
- **绝对值 → 处理 → 还原符号**，正负对称，不引入直流偏置。
  （第一版写成了 `y = x` 之后又取负，符号算错，被 `tb_audio_out` 的饱和断言当场抓到。）

### 4.2 音量表下探到 1.0×

`rtl/input/keymap8.v`：

```verilog
vol_idx <= (vol_idx >= 4'd10) ? 4'd2 : (vol_idx + 4'd1);
```

范围从 **6..10** 改成 **2..10**，上电默认仍是 6（听感合适）。
`vol_idx = 2` 对应 1.0×，此时 8 个声部全叠加也只有 `8 × 2047 = 16376`，
**连拐点都碰不到，完全线性**。现场一旦觉得糊，按到最低档就干净了。

### 4.3 屏幕音量梯重映射（`rtl/display/lcd_scope.v`）

音量梯原来 5 格（`vol_idx` 6..10），现在有 9 档（2..10）。改成 2 档一格：

```verilog
wire [4:0] vsub    = {1'b0, vol_q4} - 5'd2;
wire [4:0] vol_lvl = (vol_q4 < 4'd2)  ? 5'd0 :
                     (vol_q4 >= 4'd10) ? 5'd4 :
                     {2'b0, vsub[2:1]};
```

`vol_idx = 2,3 → 1 格；4,5 → 2 格；6,7 → 3 格；8,9 → 4 格；10 → 5 格`。
默认的 6 仍然点亮 3 格，**和修复前的视觉表现一致**。

### 4.4 `mixer16` 声像改到帧尾一次算（时序）

软限幅加进 `audio_out` 之后，综合报出最差路径
`u_mixer/mult_211_s2 → u_mixer/vp_lo_13_s`，**slack 只剩 +0.017 ns**。
原因：声像是逐声部算的，一个 9.26 ns 周期里串了
「乘法器 → 13/16 移位加 → 声像选择 → 23 位累加」四级。

改成**按声部奇偶分开累加，声像只在帧尾对两个部分和做一次**：

```verilog
// 偶数声部 -> acc_e，奇数声部 -> acc_o
// 每声部只多一次 23 位加法
out_l = sum_e + (13/16) * sum_o
out_r = sum_o + (13/16) * sum_e
out   = (sum_e + sum_o) >>> MIX_SHIFT      // 与原单声道混音逐位相同
```

数学上完全等价（声像系数按奇偶恒定，可以提到求和外面），但每声部路径只剩一次加法。
`out` 仍然等于 `sum_e + sum_o`，所以波形页、`tb_mixer16`、`tb_liss` 的期望值全部不用动。

## 7. 已知限制

1. **软限幅仍是限幅**。8 个音在 4.0× 下依然被压到 29694，只是压得平缓、不产生方波，
   所以不再有差拍"颤抖"，但音量的线性度在 4 个音以上已经不成立（听不出来，测量能看出来）。
2. **拐点/斜率是固定常数**，没有做自适应增益（AGC）。做 AGC 需要在 `audio_out` 里
   加峰值跟踪与缓慢释放，会改变单音的起音瞬态，风险大于收益，故不做。
3. **`sw5_vol`（SW3 第 5 位）仍然只做 +1 档**，与 `vol_idx` 相加后钳在 10。
   如果把它改成"音量减"，现场会多一个降低档位的物理开关 —— 目前认为长按/短按已够用，未改。

## 8. 答辩口径

> Q：多音叠加会不会削波？
> A：会有软限幅介入，但不会产生方波互调。拐点放在 3/4 满刻度，斜率 1/8，
> 8 个音叠加时压到 29694 counts 而不是拍平到 32767；音量键可以降到 1.0×，
> 那样 8 个音叠加也只有 16376 counts，完全线性。
>
> Q：为什么之前会"颤抖"？
> A：混音把 8 个声部归一化到满刻度，`audio_out` 又默认乘 4，第 4 个音就越界了。
> 硬削顶把波形变成方波，方波与各基频互调产生 |f1−f2| 的差拍，听起来像颤抖。

## 12. 后续修正：双音也颤抖，真因不在削波，而在符号扩展（2026-10-28）

第 11 节收尾时以为"发抖"已经解决。用户随后反馈（m09491 原文）：

> 双音依旧在颤抖

两个音在默认音量下只有 `1228 x 2 x 4 = 9824` counts，离 0.75 满刻度的软限幅拐点 24576 还差得远，
**根本不可能触发削波**。所以第 11 节的修复解决的是"五个音以上"的问题，双音另有原因。

### 12.1 用探针把真凶挖出来

写了一个只看 60 个样本的探针（`sim/_tn_probe.v`，用完即删），在 `latch_mode = 1` 锁存两个音后打印：

```
 idx  fx mix_out  din_q  wet_sum   t0q   rvb_s  audio_s
  55   0     389    389    131061  1296   1296     8197
  56   0     -11    -11    131061  1296   1296    32767   <-- 负半周变满刻度正
  57   0    -389   -389    131061  1296   1296    32767
```

`mix_out` 明明是 ±389 的小正弦，`audio_s` 却在负半周跳到 **+32767**。

注意 `wet_sum` 恒等于 `131061 = 0x1FFD5`：这是 `din_q` 为负时被当成无符号数送进饱和器的结果
（`-11` 的 16 位补码 `0xFFF5` 经 17 位零扩展到 `0x1FFF5`，再加上干声路径的 `0xFFF5` 就是 `0x1FFD5`）。

### 12.2 根因：`fx_echo.v` 用拼接做符号扩展

```verilog
// 错（修复前）
wire [17:0] wet_sum = {din_q[15], din_q} + echo_wet + rvb_wet + cho_wet;
wire [17:0] wb_sum  = {din_d[15], din_d} + fbg_new;
```

`{din_q[15], din_q}` 看起来像"符号扩展到 18 位"，但 **Verilog 里拼接永远是 unsigned**。
于是 `-11` 被当成 `65436`，四路相加后 `sat16` 一轮，输出被钉在 `+32767`。

听感上：每个波形的负半周被替换成一条满刻度正电平，周期性的直流跳变落在音频带内，
就是用户说的"颤抖"。而且它与音数无关——**单音也应该是坏的**，只是叠音时更明显。

### 12.3 修复

```verilog
// 对（修复后）
wire signed [17:0] wet_sum = din_q + echo_wet + rvb_wet + cho_wet;
wire signed [17:0] wb_sum  = din_d + fbg_new;
```

`din_q` 是 `reg signed [15:0]`，参与 `signed` 表达式时自动符号扩展，不需要也不应该手工拼接。
顺带把 `wet_sum` 从 `unsigned` 变成 `signed` 后，综合少了一级 17 位无符号扩展逻辑，
**Fmax 从 110.372 MHz 升到 114.0 MHz（slack +0.199 → +0.487 ns）**。

修复后同一段探针：

```
 idx  fx mix_out  din_q  wet_sum   audio_s
  55   0     389    389      -43      8197
  56   0     -11    -11     -57       -172
  57   0    -389   -389     -228      -228
```

负半周恢复正常极性。

### 12.4 补上缺失的回归

原来 `tb_fx_echo` 的所有激励都是正数，所以这个 bug 一直没被测出来。新增 5 条断言：

```verilog
check(capn >= 32, "negative dry path emits one sample per push");
check(badx == 0,  "on=0: negative samples pass through sign-correct");
check(cap[0] == -16'sd1000, "negative impulse keeps its sign (dry)");
check(badx == 0,  "negative signal never flips onto the positive rail");
check(cap[DLY] == -16'sd250, "negative echo is wet-negative (1000 -> -250)");
```

现在的 `tb_fx_echo` 是 **13 项全过**，其中 5 项专门守这条坑。

### 12.5 复盘：为什么三轮都没找到

| 轮次 | 假设 | 为什么错 |
|---|---|---|
| 1 | 混音削波 | 只在 5 个音以上成立，双音根本到不了拐点 |
| 2 | 音量下限太高 | 同上，只是让用户"没法调小"，不是发抖的来源 |
| 3 | 声像 / mixer 反馈 | mixer 完全正常，探针证明 `mix_out` 是干净的小正弦 |

**教训：从"现象与音数相关"推出"是幅度问题"是一个思维惯性。** 真正的信号是探针里
`mix_out` 小而 `audio_s` 大——只要早一步把这两条线放在一起看，就会立刻指向幅度之外的转换错误。

### 12.6 同类检查（本轮一并核过，均无问题）

| 位置 | 写法 | 结论 |
|---|---|---|
| `audio_out` 的 `prod` / `prod_sh` | 显式 `signed` | 正确 |
| `mixer16` 的 `vp_lo` / `se13` / `so13` | 全部来自 `reg signed`，无拼接 | 正确 |
| `i2s_tx` 的串行化 | 纯位操作，不涉及算术 | 无风险 |
| `lcd_scope` / `liss_render` | 只影响显示 | 无风险 |

**今后约定：凡是涉及有符号音频数据的地方，禁止用 `{sign, data}` 做符号扩展，一律交给 `signed` 算术自动处理。**

## 13. 「双音颤抖」真正的第二个原因：单键模式下来回报键

第 12 节修掉了 `fx_echo` 的符号扩展之后，用户在实物上仍然报「两个音合成出来
不像正常的声音，依旧在反复振动、颤抖」。于是把 FPGA 真正吐出来的样本接出来做
频谱分析，结论分成两件事。

### 13.1 数字链路本身是干净的双音和（实测）

测试台 `sim/_an2.v` 直接把 `key_raw` 强制成 `16'h0003`（两个音，绕过触摸芯片），
在 `dut.audio_tick` 上把 `dut.audio_s` 与 `dut.mix_out` 各 dump 8192 点。

```
n = 8220   audio min/max = -15728 16288   mix min/max = -3932 4072
--- audio_s 与 mix_out 的谱完全一致 ---
   293.27 Hz   0.0 dB     <- D4
   263.95 Hz  -0.9 dB     <- C4
   246.35 Hz -34.2 dB
   310.87 Hz -52.6 dB
   其余            -60 dB 以下
--- 包络起伏 --- 主起伏 29.67 Hz，深度 -20.3 dB
--- 样本统计 --- 相邻样本相同 77/8219 (0.9%)；max |单样本跳变| 640；贴顶样本 0 个
```

只有两根干净谱线、没有削波、没有样本重复、没有不连续。**那个 29.67 Hz 的起伏
就是 C4 与 D4 的拍频**（理论 |293.66 − 261.63| = 32.03 Hz，这里的偏差是 FFT
分辨率 5.9 Hz 造成的）。任何正确的合成器同时发这两个音都会这样，属于音程本身
的粗糙度，不是数字缺陷。同理，现在 8 个键的映射是 C 大调音阶，相邻两个键
永远只差 1~2 个半音：

| 相邻键对 | 半音数 | 拍频 |
|---|---|---|
| TP2+TP3  E4+F4 | 1 | 20.6 Hz ← 最难听 |
| TP6+TP7  B4+C5 | 1 | 30.9 Hz |
| TP0+TP1  C4+D4 | 2 | 32.0 Hz |
| TP3+TP4  F4+G4 | 2 | 39.2 Hz |
| TP5+TP6  A4+B4 | 2 | 49.2 Hz |

要听「干净的两音」，按相差五度或八度的两个键，例如 **TP0+TP4（C4+G4）** 或
**TP0+TP7（C4+C5，八度、无拍频）**。

### 13.2 真正的 bug：芯片单键模式下来回报键把锁存音翻掉

模块出厂是**单键模式**（见 `交互方案_TTP229.md`），两根手指同时按下时芯片
**每次 32 ms 扫描只报一个键，并且可能在两个键之间来回切换**。而原来的锁存规则是

```verilog
latch <= latch ^ key_rise;      // key_rise = gate_live & ~key_d
```

A 键赢得扫描时把它点亮，下一次 B 键赢得扫描时 `~key_d` 又让 A 产生上升沿，
把 A 翻掉 —— 两个音几十赫兹地忽开忽关。**这与用户描述的「反复振动」以及
「只在多指同时按才出现」完全吻合**，单指时键值稳定所以看不出问题。

### 13.3 新规则：报满 20 ms 才算一次 tap，松手前只许触发一次

`rtl/top/top_inst.v`：

```verilog
localparam [9:0] TAP_N = TAP_HOLD[9:0];        // 965 samples ~ 20 ms

always @(*)                          // 本拍是否构成一次 tap
    for (tt = 0; tt < 8; tt = tt + 1)
        tap_fire[tt] = gate_live[tt] && (tap_cnt[tt] == TAP_N - 10'd1)
                       && !tap_done[tt];

always @(posedge clk_sys)            // 只在这里推进
    if (sample_tick) begin
        for (tt = 0; tt < 8; tt = tt + 1) begin
            if (!gate_live[tt])                  tap_cnt[tt] <= 10'd0;
            else if (tap_cnt[tt] != TAP_N)       tap_cnt[tt] <= tap_cnt[tt] + 10'd1;
        end
        if (gate_live == 8'd0)  tap_done <= 8'd0;             // 全部松手 -> 重新武装
        else                    tap_done <= tap_done | tap_fire;
        if (!latch_mode) begin latch <= 8'd0; tap_done <= 8'd0; end
        else             latch <= latch_nx;                   // tap = 翻转该音
    end
```

关键在于 **`tap_done` 只在 `gate_live == 0`（所有手指都抬起）时清零**。芯片来回
切换时，每个键最多点亮一次，之后再也没有机会被翻回去，因此两指同时按会稳定
锁住两个音。`TAP_N = 965` 略小于一个扫描周期（1543 样本 / 32 ms），既保证真实
点按能触发（点按通常 > 100 ms），又保证芯片来回切换时不会误触发。

### 13.4 回归：`sim/tb_latch.v`

新增专门守这条坑的测试台（`TAP_HOLD` 参数化，跑一次约 1 s），在 `key_raw` 上
直接复现芯片的交替上报：

```
=== tb_latch: tap-to-latch vs single-key alternating reports ===
    TAP_HOLD = 8 samples, one scan = 20 samples
  ok    A1 pad0 first report : latch = 01
  ok    A2 pad1 first report : latch = 03
  ok    A3 pad0 again, no flap : latch = 03     <- 关键：不再被翻掉
  ok    A4 pad1 again, no flap : latch = 03
  ... (交替三轮共 6 次，全部保持 03)
  ok    B  all up, keeps both : latch = 03
  ok    C  pad0 tapped again : latch = 02       <- 再点一次能关掉
  ok    D  both at once : latch = 01
  ok    E  still held, stable : latch = 01
=== ALL PASS ===
```

同时给 `top_inst` 加了 `TAP_HOLD` 参数，`tb_inst` 用 `.TAP_HOLD(8)`，因为原来
锁存测试只把键按住 3 个 LCD 帧（约 12.5 ms），短于生产值 20 ms。

### 13.6 结论：两个原因不要混为一谈

- **来回报键（已修）**：两指按下时音符被反复开关，这是逻辑缺陷，现在不会了。
- **拍频（不是缺陷）**：C4+D4 相差一个全音，29~32 Hz 的起伏是物理，换任何
  合成器都一样。

> **本节的建议已被第 14 节取代。** 当时给的办法是"演示时按五度/八度组合"，
> 那是绕开而不是解决；用户按 TP0+TP1 仍然会听到抖动。第 14 节把键位布局本身
> 改成 C 大三和弦琶音，相邻格全部是三度/四度，从根上消掉了这个音程。

## 14. 第三个原因，也是最后一个：键位相邻差一个全音（2026-10-28）

### 14.1 用户反馈

三处修改都到位之后（符号扩展 `a8d98e8`、锁存加固 `48b4d8a`），实测仍然报：

> 「点 TP0，再点 TP1，两指都松开 → 依旧在颤抖」（m10085）

注意这个动作用户是**照着第 13 节的建议做的**：锁存住两个音、松手，gate 恒为 `8'h03`，
不存在任何翻键。所以剩下能听到的起伏，只可能来自这个恒定的两音和本身。

### 14.2 实测：把 DAC 数据流直接做频谱

一次性台 `sim/_an2.v`（用完已删）绕过触摸芯片，`force dut.key_raw = 16'h0003` 直接把
TP0(→C4) 与 TP1(→D4) 两个 gate 钉住，在 `dut.audio_tick` 上同时 dump `dut.audio_s`（进
I2S 的样本）和 `dut.mix_out`，各 8192 点，再用 numpy 做 FFT。

```
n = 8220   audio min/max = -15728 16288   mix min/max = -3932 4072
--- audio_s 与 mix_out 的谱完全一致 ---
   293.27 Hz    0.0 dB      <- D4
   263.95 Hz   -0.9 dB      <- C4
   246.35 Hz  -34.2 dB
   310.87 Hz  -52.6 dB
   其余            -60 dB 以下
--- 包络起伏 ---
   主起伏 = 29.67 Hz，深度 -20.3 dB（接近 100% 调幅）
--- 样本统计 ---
   相邻样本相同：77 / 8219（0.9%，正常过零）
   max |单样本跳变| = 640；mean = 226.8
   贴顶样本（|x| >= 32000）：0 个
```

**结论**：FPGA 输出的音频在数学上就是两个纯正弦的精确叠加，频谱里只有 C4 与 D4 两根
干净谱线，其余全在 −34 dB 以下；没有削波、没有样本重复、没有不连续。

那个 29.67 Hz 的起伏就是 **C4（261.63）与 D4（293.67）的拍频**，理论值 32.03 Hz。
两根等幅正弦相距一个全音，包络会周期性地降到零 —— 每秒约 30 次完全消失，
听感就是"颤抖"。任何正确的合成器弹这两个音都是这个结果。

### 14.3 修法：改音程，不改信号链

既然数字链路已经证明是干净的，剩下的只能从**音程**下手：让相邻两格都是协和音程。
`rtl/input/keymap8.v` 的 `NOTE_TAB` 从 C 大调音阶改成 C 大三和弦琶音：

```verilog
// 旧： C4 D4 E4 F4 G4 A4 B4 C5   （相邻差全音/半音 -> 32 Hz 拍频）
// 新： C4 E4 G4 C5 E5 G5 C6 E6   （相邻是大三度/小三度/纯四度）
localparam [5*8-1:0] NOTE_TAB =
    { 5'd28, 5'd24, 5'd19, 5'd16,
      5'd12, 5'd7,  5'd4,  5'd0 };
```

| 相邻格 | 音程 | 拍频 |
|---|---|---|
| TP0+TP1 | 大三度 C4→E4 | 68 Hz |
| TP1+TP2 | 小三度 E4→G4 | 62 Hz |
| TP2+TP3 | 纯四度 G4→C5 | 131 Hz |
| TP3+TP4 | 大三度 C5→E5 | 65 Hz |
| TP4+TP5 | 小三度 E5→G5 | 62 Hz |
| TP5+TP6 | 纯四度 G5→C6 | 130 Hz |
| TP6+TP7 | 大三度 C6→E6 | 65 Hz |

拍频全部抬到 62…131 Hz，离开了耳朵判为"抖动"的 ~30 Hz 粗糙度峰。叠几格按下去
仍然是一个干净的 C 大三和弦，复音演示反而更好听。

配套改动：`rtl/audio/inc_lut.v` 从 25 项扩到 29 项以容纳 E6（1318.510 Hz），
索引 0–24 的值一字未改，`test_mode.v` 的两八度布局不受影响。
`rtl/display/spectrum16.v` 的 bin 覆盖到 1.507 kHz，E6 落在 bin 14，仍在屏内。

### 14.4 三轮误判的教训

同一个描述（"多音颤抖"）实际上叠了**三个独立原因**，每修一个都能让症状看起来
"该好了"，但剩下的原因照样让人听到抖动：

| # | 原因 | 修法 | 为什么当时以为够了 |
|---|---|---|---|
| 1 | 5 音以上触发软拐点限幅 / 音量只有 6–10 档下不去 | 软限幅 + 音量下探到 2 | 只验证了"多音"，没单独验证"两音" |
| 2 | `fx_echo` 用 `{din_q[15],din_q}` 做符号扩展（拼接永远无符号） | `wire signed [17:0]` | 探针确实看到了 +32767 的异常，但那是**第二个**病灶 |
| 3 | 相邻键差一个全音，30 Hz 拍频 | 键位改成琶音 | —— |

教训：**"两音"和"多音"要分开验证**。凡是用户说"抖动/脉动"这类周期性描述，
先做一次 FFT 看谱线位置和包络起伏频率，比继续读 RTL 快得多。

## 15. 包络改成"拨弦衰减"：让 100 % 调幅落在衰减里（2026-10-29）

第 14 节的结论只对了一半：把音程从全音改成三度，**起伏的深度一点没变**——两根
等幅纯音相加，调制深度恒为 100 %，只有起伏的**快慢**从 32 Hz 变成 68 Hz。
"每秒抖 32 下"变成"每秒抖 68 下"，听感并没有变好，用户当场否掉了。

### 15.1 为什么谐波救不了

用 numpy 实测（1 ms RMS 包络、170 ms 窗、8192 点）调幅深度：

| 音色 | 调幅深度 |
|---|---|
| organ（只有基波 = 纯正弦）| **96.1 %** |
| drawbar `[1, .5, .25, .125]` | 85.6 % |
| square | 84.8 % |
| saw | 79.2 % |

谐波越多，拍峰处出现"尖锐的尖峰与深谷"，视觉与听觉上的粗糙度**反而更糟**。
早先用 200 样本（4.15 ms）平滑窗得出"谐波更好"是伪像：平滑窗≈拍频周期会把谷
抹平。**必须用 <1 ms 的平滑窗才看得到真实深度。**

失谐多副本（想摧毁相干拍频）同样无效：2 副本 ±8/±15/±25 cent → 99.2/97.9/98.2 %；
3 副本 ±15/±25/±40 cent → 98.4/98.9/98.6 %。

### 15.2 真正的做法：让包络在几百毫秒内衰减到零

`rtl/top/top_inst.v` 参数从

```verilog
parameter integer DEC_STEP = 2,
parameter integer SUSTAIN  = 12'd60000,
```

改成

```verilog
parameter integer DEC_STEP = 1,
parameter integer SUSTAIN  = 16'd0,
```

`adsr.v` 的状态机一行没动：`S_DEC` 里 `env <= SUSTAIN + DEC_STEP`，`SUSTAIN=0`、
`DEC_STEP=1` 时 `env` 从 65535 每样本减 1，到 1 时 `env <= 1` 仍 > 0 → 下一拍
`env-1 = 0`，进 `S_SUS` 且 `active` 保持 1。等于**自动衰减到静音后停住**。
攻击 4.0 ms、衰减 1359 ms、释放 226.5 ms。

效果：和弦不再是一堵持续互相拍频的墙，而是一串"拨响"，100 % 调幅只作用在
快速衰减的尾巴上，人耳感知不到。真实乐器（吉他、钢琴、马林巴）都是这个包络。

`tb_inst` / `tb_latch` / `tb_adsr` 都自己覆盖 `SUSTAIN`/`DEC_STEP`，所以 16 个
平台全 PASS，一条断言都不需要改。

### 15.3 构建

Fmax 108.019 MHz、slack +0.002 ns、0 违例端点；35 管脚逐条核对未变。
位流 sha256 `3C2FF22CD7485AC1…`。

## 16. 波形页"跳"的真正原因：滚动显示在这块屏上根本不可能稳（2026-10-30 ~ 10-31）

用户总共六轮说"波形图一直在跳"。第五轮给出了决定性线索：

> "我用锁存模式，按下 TP0 和 TP1 的时间并不相同，他们相位根本对不齐，
> 导致我看到的波形图一直在跳"

第六轮（这一节真正被解决的那一次）：

> "波形依旧不稳，你先找一下问题"（m12563）

结论先说：**换触发算法救不了，因为问题不在触发，在"滚动"这个显示方式本身。**
最终把波形页从"滚动示波器"改成"单次捕获快照"，画面才真正静下来（第 16.7 节）。

### 16.1 先回答"画的是合成之后的信号吗"

是。`rtl/top/top_inst.v` 里 `wire signed [15:0] scope_s = mix_out;`，取的就是
`mixer16` 的 8 声部求和输出，频谱页也是同一个节点。

### 16.2 量化出来的硬缺陷

| 量 | 值 |
|---|---|
| 每帧前进的采样数 | 804（48.214 kHz ÷ 60 Hz）|
| 波形历史缓存深度 | **512**（`wave_buf`，1 块 BSRAM）|
| 一屏显示 | 480 列 = 9.96 ms |
| 窗口起点（start trigger）| 必须在触发点上 → 触发点至少 480 样本旧 |
| **因此合法触发点只剩** | **480…511，共 32 个样本** |
| C4/E4 过零间隔 | 81…245，均值 147 |
| C4+E4 拍频周期 | **709 样本** |

原代码 `cz_age[ci] < 11'd960` 允许年龄到 960，但 512 深的缓存里 age>511 的地址
**早已被覆盖**，指向的根本不是那个过零点。单音时任意起点看起来都一样（所以
"单音很稳"），双音时不同起点对应拍频包络的不同位置 → 每帧形状不同 → 跳。
### 16.3 第一次尝试（失败，已回退）：2048×32 + 包络峰触发

把 `wave_buf` 深度加到 2048×32（4 块 BSRAM），触发改成"包络峰优先 + 过零兜底"
的 4 项事件队列，并写了 `sim/tb_wavetrig.v` 逐帧比对 480 个样本来证明画面确实
冻结（5 项全过）。

**但综合两次都违例**：

| 版本 | Logic | BSRAM | Actual Fmax | 违例端点 |
|---|---|---|---|---|
| 2048×32，NEV=8 | 4973 | 14/46 | 107.574 MHz | 3 |
| 2048×32，NEV=4 | 4775 | 14/46 | **104.914 MHz** | 8 |

把队列从 8 减到 4 反而更差 → 降速不是队列深度造成的，而是 +3 块 BSRAM 与
11 位读地址把回退版本来只剩 +0.003 ns 的余量直接吃穿（`docs/Fmax加固记录.md`
第 4 节记录的天花板 ~108.5 MHz 是真实存在的）。已 `git checkout` 回退。

### 16.4 第二次尝试：1024×16 + 用声部 0 触发（实机仍跳）

两个关键改动：

1. **深度 1024、宽度 16**（新建 `rtl/display/wave_hist.v`）。1024×16 = 16 Kbit，
   仍然只占 **1 块 BSRAM**（2048×32 要 4 块）。深度翻倍后合法年龄带变成
   480…1023。宽度减到 16 位也正好：波形只画 136 行，8 位量化会让台阶变成
   可见的 8 行锯齿。
2. **触发源换成 0 号声部的符号位** `raw_flat[15]`，不再比混音。0 号振荡器不管
   有没有按键都在跑相位，天然严格周期；而且是 1 个触发器，不是 16 位比较器 +
   `mix_prev` 寄存器。

```verilog
reg  v0_neg_q;
wire v0_neg = raw_flat[15];          // voice 0 sign bit
wire xing   = v0_neg_q && !v0_neg;   // rising zero crossing of voice 0
```

年龄带 `(cz_age[ci] >= SPAN) && (cz_age[ci] <= 11'd1023)`，无合法点时回退自由运行。

这次综合反而更快（Fmax 111.888 MHz、slack +0.322 ns、逻辑级数 9→4），因为顺手
删掉了挂在 `mix_out` 上的 16 位 `mix_prev` 寄存器和比较器——那条链原本就在
`clk_sys` 的最紧路径上。

**但实机上画面照样跳。** 用户第六次反馈：

> "波形依旧不稳，你先找一下问题"（m12563）

### 16.5 探针抓到的三个真 bug（`sim/_wf.v`，用完已删）

按帧抓页面真正要画的 480 个样本 `u_buf_w.mem[(base_w+i) & 1023]`，与上一帧比
MAD：

```
frame 1  v0x=1 wptr=394 base=0   (+0)   trig=1 MAD=0
frame 3  v0x=1 wptr=796 base=123 (+123) trig=0 MAD=540
frame 5  v0x=1 wptr=174 base=525 (+201) trig=0 MAD=2451
frame 8  v0x=1 wptr=777 base=83  (+840) trig=1 MAD=1900
```

`trig_ok` 绝大多数帧是 0。顺着查下去，三个独立的错：

1. **年龄表只有 3 格，过零槽却有 4 个**：`reg [9:0] cz [0:3];` 配
   `reg [10:0] cz_age [0:2];`。C4 的过零间隔是 184 样本，三格年龄只能取到
   0/184/368，**永远进不了 [480,1023] 合法带** → `trig_ok` 恒 0。之前看到的
   `trig_ok=1` 是复位初值 `cz_age<=200/400/600` 造成的假象（600 落在带内）。
2. **`ax` 取绝对值写错**：`wire [16:0] ax = scope_s[15] ? {1'b0, (~scope_s + 17'd1)} : {1'b0, scope_s};`
   —— `~scope_s` 是 16 位无符号，`+17'd1` 只做零扩展，负样本得到 65536−|x| 而不是
   |x|，于是 `epk` 冲到 52000（超过满刻度 32768），阈值 `thr_hi` 永远不可达。
   正确写法是先符号扩展到 signed 再加一：
   ```verilog
   wire signed [16:0] sx = scope_s;
   wire [16:0] ax  = sx[16] ? (~sx + 17'd1) : sx;
   ```
3. **包络峰检测的重新武装阈值不可达**：一阶低通 `tau = 10.6 ms`（`>>>9`）把
   100 % 调幅吃成约 1 : 1.85，半高阈值 `thr_lo = epk - (epk>>>1)` 永远到不了
   → `armed` 粘在 0，整段只出过一个峰。

三个都修完之后，`trig_ok` 每帧确实为 1 了，但 **MAD 还是 1700–1900**。

### 16.6 定论：滚动显示在这个分辨率下不可能稳

修好之后继续追，边界全部撞在同一处：

| 尝试 | 结果 |
|---|---|
| 过零触发（1024 深、480 窗口、触发点在最左列）| 合法带 480…1023 只有 544 宽 < 一个拍 **709** → 每 709 样本里有 165 个样本没有任何可用事件，只能自由滚动 |
| 把触发点挪到第 96 列（窗口起点 = 事件地址 − 96）| 可用带 96…927 = 832 > 709，`trig_ok` 每帧都为 1；但 `base` 每帧仍 +184/+185（选中的是过零点），MAD 1700–1900 |
| 只在 `base` 不变时冻结 | 只能维持 3 帧。写入器每帧推进 **804** 个样本，1024 深的历史 1.3 帧就被覆盖一遍，固定基址的内容随即换掉 |

根因不是某个 bug，而是**采样率与帧率的关系**：每显示一帧就要消费 804 个样本，
而历史只有 1024 深。任何"锚在写指针或某个事件上"的窗口都会逐帧落到不同的切片；
固定基址又会被写入器覆盖。**周期信号在滚动显示上不可能静止**——这和信号本身
干不干净无关。

### 16.7 最终做法：单次捕获快照

不再滚动。改成"**换按键 → 等包络稳定 → 抓 480 个样本 → 一直显示它们**"：

```verilog
parameter integer SETTLE = 14_460      // 300 ms at 48.214 kHz
reg cap_run, cap_arm, cap_go;
reg [9:0] cap_cnt;
reg [15:0] settle;
reg [7:0]  gate_q;
wire gate_chg = (gate != gate_q);
wire cap_we   = scope_tick && cap_run;
```

- 按下的格子一变（`gate_chg`）→ `settle <= 0; cap_arm <= 1`
- `settle` 数满 `SETTLE`（默认 300 ms，足够让起音走完）→ 发一次 `cap_go`
- `cap_go` 之后连续写 480 个样本到地址 `cap_cnt = 0..479`，写完置 `cap_run <= 0`，
  **缓冲保持不动**
- `lcd_scope` 侧：`wire [9:0] wstart = 10'd0;`，窗口永远从地址 0 开始；原来的
  `trig_addr` / `trig_ok` 两个端口已删除

语义上的取舍：按住和弦期间画面绝对静止；代价是松开一个音时画面要等 300 ms 才
更新，而且**看不到"最新"的波形**（永远是最近一次换把位时抓的那一屏）。对一个
"看清这个和弦长什么样"的教学示波器，这是对的取舍。

### 16.8 验收

### 16.9 仍然看不到"完整纺锤"是正常的

`docs/两音合成波形.png` 画的是这件事：C4+E4 的拍频 68 Hz，一个拍 = 14.71 ms =
**709 个样本**，而一屏只有 **480 列 = 9.96 ms**，窗口本身就短于一个拍（差 32 %）。
所以屏幕上永远只截到纺锤的一段。这是"窗口宽度 vs 拍周期"，不是 bug，也**不是
合成出错**。那个 68 Hz 的包络同时也是耳朵听到的"抖"的物理来源——把显示修静了
不会让拍频消失。

### 16.10 五轮误判的共同教训

| 轮次 | 当时的判断 | 为什么错 |
|---|---|---|
| 1 | 混音削波 | 双音稳态只有满刻度的 30 % |
| 2 | `fx_echo` 符号扩展 | 修的是真 bug，但与两音抖动无关 |
| 3 | 锁存来回报键 | 修的是真 bug，用户已经"两指松开"仍抖 |
| 4 | 音程差一个全音 | 只是把 32 Hz 换成 68 Hz，**调制深度 100 % 没变** |
| 5 | 换成声部 0 触发就稳了 | 触发器根本没有生效（三个 bug），且滚动显示本身就不可能稳 |

两条方法上的教训：

1. **自检台一开始只比"第 0 列"**（构造上永远是过零点），载体锁定被误判成画面冻结。
   判据必须比较整窗，或者避开触发点所在的列。
2. **先算"能不能"再写代码**。每帧消费 804、历史 1024，这两个数一摆出来就该知道
   滚动方案不可能成立，不必等三轮构建。
