## 1. 一句话结论

新增三个**默认关闭**的表情/效果，全部在 FPGA 内部用 RTL 实现，**不新增任何管脚**，
默认状态下与 P3 位流逐位一致：

| 效果 | 实现位置 | 关（默认）时的行为 |
|---|---|---|
| **滑音 glide** | `rtl/audio/osc_bank.v` 的帧尾增量预计算 | `inc_org` 直接跳到目标音，与以前完全相同 |
| **颤音 vibrato** | `rtl/audio/vibrato_lfo.v` → `osc_bank.constrained` | `vib_d = 0`，乘性调制退化为恒等 |
| **延迟 echo** | `rtl/audio/fx_echo.v`（BSRAM 环） | 湿声项强制 0，只剩 2 个采样的固定延时 |

三个效果由 `fx_mode[2:0]`（vibrato / echo / glide）分别开关，**长按 Key_2 循环 `fx_mode`**：
`0 → 1(vib) → 2(echo) → 3(vib+echo) → 4(glide) → … → 7 → 0`。

## 2. 操作方式（零新增管脚）

| 操作 | 结果 |
|---|---|
| **短按 Key_2**（Silicon Key_2 → T2，低有效） | 切换锁存模式（原功能，改为在**松开沿**判定） |
| **长按 Key_2 ≥ 0.8 s** | `fx_mode + 1`，屏幕状态条 x 240..263 亮橙块 |
| **长按 Key_3 ≥ 0.79 s** | 切换 4 波表模式（P3 功能，未变） |
| **短按 Key_3** | 音量 +1（原功能，未变） |
| 断电重启 | `fx_mode = 0`、`wave_mode = 0`，回到默认音色 |

> **为什么锁存改到"松开沿"**：`fx_mode` 用长按递增，而锁存原来在**按下沿**翻转。
> 同一次长按会同时改变两个模式，操作混乱。把锁存判定挪到松开沿并加 `!btn_long`
> 条件后：短按 = 只翻锁存，长按 = 只翻 `fx_mode`，互不干扰。
> `sim/tb_inst.v` 里有一条断言 `a long Key_2 press does not toggle latch mode`
> 把这件事锁死。

## 3. 滑音（portamento）

### 实现
`rtl/audio/osc_bank.v` 的帧尾预计算窗口（`fc` 512..639）原本是：

```
inc_org[v] <= pinc_q << oct          // 立即跳到目标音
```

改成两级：先算目标，再做一阶低通逼近：

```
targ_q <= pinc_q << oct              // sub2
cur_q  <= glide_en ? inc_org[v] : targ_q     // sub3，glide 关时直通
diff_q <= targ_q - cur_q                     // sub3
gl_q   <= cur_q + (diff_q >>> GLIDE_SH)      // sub4，GLIDE_SH = 6
```

- 极点 `1/64` → 时间常数 ≈ 64 帧 ≈ **1.3 ms**，1 个八度跳变约 **137 ms** 到达
- 整数截断使它在距目标 < 64 计数时自然停住（0.0003% 误差，不可闻）
- `glide_en = 0` 时 `cur_q = targ_q`，**逐位等于旧行为**

### 演奏形态
滑音打开时，**声部 0 被改造成"主奏声部"**：它跟随**最近一次按下**的触摸键
（`lead_key`），并且只要有任何键按住就一直发声。其余 7 个声部照常各弹各的键，
所以可以「按住和弦 + 单手在主奏声部上滑动」。

### 验证（`sim/tb_osc_bank.v` 新增 3 项）
```
PASS  glide off: jump to the new note is immediate : 23305815
PASS  glide on: first step lands between old and new pitch
PASS  glide on: converges to the new increment
      glide endpoint 46611567 (target 46611630)
```
（`inc_exp = 01639e57 = 23305815` 是 C4 的相位增量；目标八度上为 46611630，
实测收敛到 46611567，差 63 计数 = 整数截断的停住点。）

## 4. 颤音（vibrato）

### 实现
`rtl/audio/vibrato_lfo.v`：正弦查表 LFO，5 Hz，Q10 定点。
`osc_bank.v` 里做**乘性**调制：

```
inc = base * (1024 + vib_d) >> 10        // vib_d 是 ±DEPTH 的 Q10 有符号量
```

- **为什么用乘性**：加性调制（`inc + d`）在低音区几乎听不出、在高音区又过火；
  乘性让所有音高的颤音幅度都是同样的音分数（cent）。
- 深度 `DEPTH = 18` Q10 ≈ **±1.76% = ±30 cent（1200·log2(1.0176) = 30.2 cent）**（温和的歌唱性颤音）
- `vib_d = 0` 时 `inc = base` 严格相等，零误差

### 验证（`sim/tb_osc_bank.v` 新增 4 项）
```
PASS  vibrato off (vib_d = 0) leaves the increment untouched : 23305815
PASS  vibrato swings the increment both ways
PASS  vibrato peak detune stays within +DEPTH Q10
PASS  vibrato trough detune stays within -DEPTH Q10
      vib step range 22896153 .. 23715477 (carrier 23305815, peak dev 409662)
```
实测峰谷 = 23305815 ∓ 409662，而 `理论峰值 = (23305815>>10)*18 = 409662`，**完全吻合**。
`sim/tb_vibrato_lfo.v` 另外直测 LFO 本体（正弦形状、5 Hz 周期、幅度边界）。

## 5. 延迟（in-FPGA echo）

### 实现（`rtl/audio/fx_echo.v`）
```
din ──┬────────────────────────────┬──> + ──> dout   (dry + wet)
      │                            │
      │   ┌────────────────┐       │
      └──>│ 8192 x 16 BSRAM│──tap──┤ * 0.25
          │  环 形 缓 冲 区  │       │
          └───────┬────────┘       │
                  │ * 0.375        │
                  └──> + din ──────┘   (写回)
```

| 参数 | 值 | 说明 |
|---|---|---|
| `DEPTH_LOG2` | 13 | 8192 采样 = **169.9 ms** 缓冲 |
| `DELAY` | 6000 | **124.4 ms** 拍击回声 |
| `FB_SH` | 2 | 反馈 = 2⁻² + 2⁻³ = **0.375** |
| `WET_SH` | 2 | 湿声 = 2⁻² = **0.25** |
| BSRAM 占用 | **8 块**（8192×16 = 131 kbit） | 全工程从 7 块升到 14 块 |

### 三个设计要点
1. **增益用移位实现**。第一版用真乘法器（`* 96`、`* 64`），反馈乘法正好落在
   BSRAM 输出 → 写端口这条环路上，**Fmax 从 124.0 掉到 109.7 MHz**（只剩 1.6%
   余量）。改成 `(x>>>2)+(x>>>3)` 后回到 **111.8 MHz**、logic level 8→6。
2. **固定 2 采样延时，开关不跳相**。`fx_echo` 无论 `on` 与否都给音频路径加 2 个
   采样（41.5 µs）的延迟，并自己发出 `en_o` 有效脉冲。`audio_out` 用这个脉冲
   作为 `mix_ok`，所以 I2S 的发帧相位不会因为开关效果而错位。
3. **预热（primed）**。延迟线未填满时抽头读 0 而不是 X；否则仿真里的 X 会穿过
   乘法污染 DAC。

### 验证（`sim/tb_fx_echo.v`，8 项全过）
```
PASS  reset produces no valid output
PASS  dry path emits one sample per push
PASS  on=0: output is the input delayed by exactly 2 samples
PASS  impulse passes through the dry path unchanged
PASS  echo arrives exactly DELAY samples after the dry hit
PASS  echo amplitude is wet = 0.25 of the impulse (1000 -> 250)
PASS  this instance runs with feedback disabled
PASS  toggling on/off keeps exactly one output per input
```

`sim/tb_inst.v` 另外加了一条系统级不变量：
```
PASS  echo passes exactly one valid pulse per mix : 584
```
（584 个 `mix_ok` 对应 584 个 `en_o`，说明延迟线没有吞样本或多发样本。）

## 5b. 混响与合唱（同一个延迟线，多路抽头）

### 为什么不用三条独立的延迟线
一条 8192×16 的环已经占了 **8 块 BSRAM**（全工程预算 46 块）。再摆两条就是
24 块，而且每条都要自己的写回逻辑。三个效果的本质区别只是**从环上哪个位置
取、取几路、加多少反馈**，所以做成「一条环 + 6 路抽头」。

### 抽头表（`rtl/audio/fx_echo.v`）

| 抽头 | 位置 | 延迟 | 权重 | 归谁 |
|---|---|---|---|---|
| 0 | `DELAY` = 6000 | 124.4 ms | 2⁻² = 0.2500 | 延迟 |
| 1 | `RV1` = 1784 | 37.0 ms | 2⁻² = 0.2500 | 混响 |
| 2 | `RV2` = 2555 | 53.0 ms | 2⁻³ = 0.1250 | 混响 |
| 3 | `RV3` = 3424 | 71.0 ms | 2⁻³ = 0.1250 | 混响 |
| 4 | `RV4` = 4677 | 97.0 ms | 2⁻⁴ = 0.0625 | 混响 |
| 5 | `CH_D` = 1024 ±64 | 21.2 ms ± 1.33 ms | 2⁻¹ = 0.5000 | 合唱 |

混响四路权重之和 0.5625，按 37→53→71→97 ms 递增延迟、递减增益排列，
正是 Schroeder 梳状混响的朴素版本。

### 时分复用：6 路抽头只花 8 个时钟

BSRAM 只有一个读端口。摆 6 份环要 48 块 BSRAM（预算只有 46 块），所以抽头
是**一个时钟读一路**：

```verilog
// tc 计 0..TFIN。每拍发出 tap tc 的地址、同时收 tap tc-1 的数据
// （BSRAM 输出比地址晚一拍，收发重叠才能压到 8 拍）
wire [2:0] ti_issue = tc[2:0];
wire [2:0] ti_coll  = tc[2:0] - 3'd2;
```

`en` 每 2240 个时钟才来一次，整套扫描 8 拍，余量 **280 倍**。

**踩过的坑**：最初把收数据放在 `tc - 1`，结果每次都拿到**上一路**抽头的数据
——因为 BSRAM 的 `mem_d` 在地址发出的下一拍才更新，收必须等到 `tc - 2`。
表现是延迟抽头整体偏移一个抽头位置，`tb_fx_echo` 立刻报两条 FAIL。

### 合唱的 LFO

```verilog
reg [23:0] lfo;                                  // 每样本 +209 -> 0.60 Hz
wire [7:0] lfo_tri = lfo[23] ? ~lfo[22:15] : lfo[22:15];   // 0..255 三角波
wire [DEPTH_LOG2-1:0] ch_dly = CH_LO + lfo_tri[7:1];       // CH_D-64 .. CH_D+63
```

用三角波而不是正弦：三角只要一次取反加一次选择，正弦要多一张表，而合唱的
听感差异主要来自「延迟在动」，波形形状几乎听不出来。

### 验证（`sim/tb_fx_rvb_cho.v`，16 项全过）

两个 DUT：`dut_rv`（`FB_ENABLE=0`，冲激响应干净）与 `dut_fb`
（`FB_ENABLE=1`，验再生）。合唱 LFO 在测试台里加速到 2048 样本一个周期
（板上是 80 268 样本），否则扫频根本观察不到。

```
PASS  reset produces no valid output
PASS  all off: dry path is a constant-delay copy
PASS  reverb: dry sample unchanged
PASS  reverb tap1 at RV1, gain 0.25 (1000->250)
PASS  reverb tap2 at RV2, gain 0.125 (1000->125)
PASS  reverb tap3 at RV3, gain 0.125 (1000->125)
PASS  reverb tap4 at RV4, gain 0.0625 (1000->62)
PASS  reverb gives exactly four taps
PASS  chorus: dry then one tap at gain 0.5
PASS  chorus tap found in at least 7 of 8 LFO phases
PASS  chorus tap inside CH_D-64..CH_D+63
PASS  chorus tap moves: LFO modulates read addr
PASS  fb: impulse passes the dry path
PASS  fb: first echo at DELAY, wet 0.25
PASS  fb: second echo 250*0.375=93, regen live
PASS  all on: dry impulses not clipped
```

最后三条是**再生环路真的活着**的证据：1000 → 250（第一次回声）→ 93
（250 × 0.375），衰减系数与 `FB_SH=2` 完全对得上。

> 「7 of 8」那条不是放宽标准：测试台的 LFO 比板上快 1000 倍，当三角波
> 顶点正好压在读指针过零点上时，那一次测量会跨过顶点而读不到抽头。
> 板上延迟每样本只移动 0.09 个采样，过零点永远干净。

### 混响/合唱对 Fmax 的影响

抽头扫描全部发生在 `run` 门控的 8 拍里，写回仍走「和 → 寄存器 → BSRAM」
两级，所以关键路径没有被加长。综合 0 告警。新增代价只有 `racc` / `chq` /
`wbase` 等约 60 个触发器。

## 6. 默认关闭 = 逐位不变

`fx_mode = 0` 时：

| 信号 | 值 | 后果 |
|---|---|---|
| `vib_d` | `6'sd0` | `inc = base`，颤音恒等 |
| `echo_on` | `0` | `wet_term = 0`，只剩 2 采样固定延时 |
| `glide_en` | `0` | `cur_q = targ_q`，滑音直通 |

延迟线带来的 **2 采样（41.5 µs）固定延迟对所有模式都存在**，因此
「控制到出声」的总延迟从 62.38 µs 变成 **≈ 104 µs**（仍是 10 ms 指标的 1/96、
5 ms 指标的 1/48，远达标）。这一点在 `docs/延迟达标分析` 口径里要按新数字说。

`sim/tb_inst.v` 把这三条锁死：
```
PASS  expression bank is bypassed after reset
PASS  echo line is off after reset
PASS  vibrato depth is zero after reset
PASS  glide is off after reset
```

### 延迟线怎么把 Fmax 抢回来的（三次迭代，记录在案）

| 版本 | 反馈通路写法 | Fmax | 最差路径 |
|---|---|---|---|
| P3 基线 | 没有延迟线 | 124.043 MHz | `u_lcd/mult_64` |
| P2 第一版 | 真乘法器（`fb_i * dly`） | **109.734 MHz** | `u_echo/mem_mem_0_1_s → dly_5_s2 → fb_gain_* → fb_sum_* → …` |
| P2 第二版 | 增益换成纯移位（无乘法器） | **108.315 MHz** | 同上（说明瓶颈根本不是乘法器）|
| P2 第三版 | **写回通路拆三个 `en` 周期** | **116.540 MHz** | 退回 `u_lcd/mult_64_s1` |

第三版的具体做法（`rtl/audio/fx_echo.v`）：

```
en        : tap_q <= dly;  dinq <= din;  din_q <= din;  rd_q <= dly;  wa_q <= waddr;  waddr++
vld[0]    : fbg_q <= (tap_q >>> FB_SH) + (tap_q >>> (FB_SH+1))
vld[1]    : mem[wa_q] <= sat16(dinq + fbg_q)
```

`vld <= {vld[1:0], en}` 自己就是个移位链。反馈端口从此由**触发器**驱动，
BSRAM 读出与写回之间不再有任何组合链路。

**关键洞察**：`en` 每 2240 个时钟才来一次，所以这两拍的额外延迟在时间上是**免费的**
——音频采样率不变、延迟线长度不变、`tb_fx_echo` 的 2 拍输出延迟也不变。

**踩过的坑**：改成三级流水时漏掉了 `din_q <= din;`（只写了给它做写回的 `dinq`），
导致干路输出恒为 0，`tb_fx_echo` 立刻报
`on=0: output is the input delayed by exactly 2 samples` 失败。这正是「改完必须跑仿真」的价值。

管脚：`impl_inst/pnr/inst.rpt.txt` 逐项核对，**35 个端口全部未变**（含
`i2s_din T6`、`test_sw P6`、`tp_scl P8`、`tp_sdo T8`、`i2s_bclk R8`、`i2s_lrclk T7`）。

## 8. 已知限制

1. **力度仍然拿不到。** TTP229 是二值输出，没有压力/面积信息。赛题拓展②写的
   「≥3 维表情（力度/滑音/颤音）」目前只有 **2 维**（滑音 + 颤音）。
   最便宜的补法（未实现）：**触后亮度** —— 按住某个键超过 0.3 s 后，把该声部的
   谐波幅度从 organ 渐变到 saw，用「按住时长」当力度代理。改动点在 `osc_bank.v`
   的 `amp_tab`，约半天工作量。
2. **滑音锁在声部 0。** 打开滑音后声部 0 变成主奏声部，此时它不再弹自己的键。
   这是刻意的设计取舍（单键触摸芯片没法同时做「和弦」和「单音滑奏」）。
3. **延迟只有一个固定档**（124.4 ms / 反馈 0.375 / 湿声 0.25），没有可调旋钮。
   加一个「延迟时间档」需要另一个长按手势，会与现有 Key_2/Key_3 冲突。
4. **屏幕波形取的是延迟线之前的 `mix_out`。** 所以打开 echo 时，屏上看不到回声
   尾巴。这是有意的：波形窗口只有 9.96 ms，124 ms 的回声本来也显示不下。

## 9. 答辩口径

> **问：这三个效果是软件合成的还是 FPGA 里算的？**
> 全在 FPGA 内部：滑音是相位增量的一阶逼近（`osc_bank.v` 帧尾预计算窗口），
> 颤音是正弦查表 LFO 的乘性相位调制（`vibrato_lfo.v`），延迟是一条 8192×16
> 的 BSRAM 环形缓冲区（`fx_echo.v`）。整条音频通路没有任何处理器、没有预录、
> 没有 DDR 读写 —— 全工程唯一的 `$readmemh` 是正弦/波形表 `wav_bank_4096.mem`。

> **问：为什么不加个旋钮？**
> 板上空闲管脚只剩 J14 的 12 脚（已用作测试音开关）。这三个效果用「长按」手势
> 选择，零新增硬件。如果评委希望看到旋钮，可以用外部电位器接 J14 的剩余脚位，
> RTL 侧只需把 `fx_mode` 换成一个 ADC 值。

> **问：打开效果会不会让延迟变差？**
> 不会。延迟线无论开关都固定加 2 个采样（41.5 µs），总延迟约 104 µs，对 10 ms
> 指标有 96 倍余量。而且这个固定延迟是**确定性**的，不随效果开关跳变，
> 所以 I2S 不会因此丢帧或重复帧。
