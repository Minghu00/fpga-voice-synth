# 李萨如（X-Y）显示页 —— 实现与证据

> 对应赛题：**拓展功能③** 的「波形显示」进阶项（X-Y / 李萨如图形）。
> 交付物：`rtl/display/liss_render.v` + `rtl/display/lcd_scope.v` 第三页 + `sim/tb_liss.v`
> 位流：`impl_inst/pnr/inst.fs`（7,264,154 B，sha256 前缀 `218B5DFCC672CE3C`）

---

## 1. 一句话结论

屏幕第三页把 **左声道样本作横轴、右声道样本作纵轴**，每帧用 512 个立体声采样重建
一张 480×136 的 X-Y 图形，全部工作在行消隐里完成，**零额外管脚、零额外按键**。

| 页 | `dmode` | 内容 | 进入方式 |
|---|---|---|---|
| 波形页 | `2'd0` | 480 点滚动示波器 + 包络 | 上电默认 |
| 频谱页 | `2'd1` | 16 根实时频谱柱（94.17 Hz/bin） | Key_2 超长按 1.6 s |
| **李萨如页** | **`2'd2`** | **左右声道 X-Y 图** | **再按一次** |

第三页之后回到波形页，三页循环。状态条 `x 320..367` 的四格显示当前页码。

---

## 2. 为什么必须「预渲染」

光栅扫描屏幕的**列号是扫描给的**，而李萨如要求**列号由左声道样本决定**。这两件事天然冲突，
所以不能边扫边画。做法是每帧先把图形压成一张**按列的纵向拉幅表**：

```
for i in 0..511
    xb = clamp(240 + (L[i] >>> 6), 0, 479)     // 左声道 → 列
    y  = clamp( 68 + (R[i] >>> 6), 0, 135)     // 右声道 → 行
    ymin[xb] = min(ymin[xb], y)
    ymax[xb] = max(ymax[xb], y)
```

显示时第 x 列只要从 `ymin[x]` 画到 `ymax[x]`，**和波形页、包络页用的是同一个「纵向线段」技巧**。

### 为什么用 span 表而不是 1 bit 帧缓存
480×136 的位图是 65280 bit，但每个点要随机写单个 bit，等于对字节阵列做读-改-写。
span 表是 512×16 bit = **1 块 BSRAM**，读-改-写本来就是 16 bit 宽，一个点只需一读一写。
唯一的代价是**重叠的分支会被填成实心带**而不是画成两笔——真实的模拟 X-Y 示波器也是这个样子。

### 空列标记
没有采样的列存成 `{ymax=0, ymin=255}`，显示端用 `ymin > ymax` 判空。

### 缩放
`>>> 6` 即 1 count = 1/64 像素，满量程 ±32768 对应 ±512 像素，所以几万 counts 的和弦落在 136 行框内；
两端都做钳位，满幅信号不会回绕到另一端（`tb_liss` 第 5、6 项专门验这个）。

## 3. 为什么先把声部做成声像

如果左右声道内容**完全相同**，X-Y 图退化成一条 45° 直线，不是李萨如。所以 `rtl/audio/mixer16.v`
增加了轻微声像（用户已在 m05690 批准）：

```
pan_r = v[0]                                  // 声部号最低位决定偏向
vp_lo = vp - (vp >>> 4) - (vp >>> 3)  ≈ 0.8125 vp   // 偏左的声部
vp_hi = vp + (vp >>> 4) + (vp >>> 3)  ≈ 1.1875 vp   // 偏右的声部
out_l / out_r 各自累加
```

单声道兼容性靠 `L + R = 2 × 原混音` 保住（两个系数之和恒为 2）。
据此 `mixer16` 的输出从 1 路拆成 `out_l` / `out_r`，`wave_buf` 改为立体声（`{wr_data_r, wr_data_l}` 一个 32 位字）。

**注意**：单音、且所有声部同相时，左右仍是同一波形的不同缩放，X-Y 图上表现为一条斜线或一个很窄的椭圆。
这是物理事实，不是 bug——真实的 X-Y 示波器接单声道源也是这条线。**和弦、颤音、延迟打开后图形才会张开**。

## 4. 时序：全部塞进行消隐

| 项 | 数 |
|---|---|
| 清表 | 512 clk |
| 累加 | 512 × 6 clk = 3072 clk |
| **合计** | **3584 clk** |
| 行消隐预算 | 14 行 × 525 px × `DIV`(=12) clk = **88200 clk** |

余量 24 倍。因为更新发生在消隐期，**一块 RAM 就够**：它破坏的正是刚刚显示完的那一帧，
新图在下一个有效区开始前已经备好。

其次序状态机：

```
M_IDLE --(vblank 上升沿)--> M_CLR(512) --> M_H0..M_H5(512 次)
M_H0  hist_addr <= i
M_H1  hl_q <= hist_l, hr_q <= hist_r        // wave_buf 读延迟 1 clk
M_H2  yv_q <= f(hr_q);  raddr <= f(hl_q)    // BSRAM 读请求
M_H3  waddr <= raddr                        // 读在飞行中
M_H4  读出值 + 新点合并 -> 写回
M_H5  cnt++
```

渲染器**独占第二个 `wave_buf` 实例**（同一份数据、同一个写地址），因为显示端在同一时刻正在扫读
主缓冲，一块 RAM 的两个端口不够用。

### 本轮做的一次时序抢救
第一版把状态条的块号译码留在组合逻辑里，最差路径是
`u_lcd/m_stat → 5 级 LUT → nb`（0.013 ns slack）。把 `sblk`、7 个窗口标志
**提前一级寄存**（`sbk_q` / `ioct_q` / `itim_q` / `ivol_q` / `itst_q` / `iwav_q` / `ifx_q` / `idm_q`）后，
该路径退出关键集，关键路径转为 `u_spec/bctr → u_spec/re_re`（频谱的地址计算）。

### 已知风险（必须写清楚）
**Fmax 余量只有 0.14 %**。当前这次构建 TNS 为 0、0 告警，即通过了 108 MHz 约束，
但换一次布线种子有可能失败。若要加固，下一步应把 `spectrum16` 的 sin/cos 地址计算再打一拍。
用户已知悉并选择优先完成功能（m08321）。

## 7. 现场怎么看

1. 上电，屏幕停在**波形页**，弹一个音确认有波形。
2. **按住 Key_2 约 1.6 秒**，进入**频谱页**，看到 16 根柱。
3. **再按住 Key_2 约 1.6 秒**，进入**李萨如页**。
   - 弹**单个音**：看到一条斜线或很窄的椭圆（左右同源的必然结果）。
   - 弹**和弦**（多个键，锁存模式下可先锁几个音）：图形张开成真正的二维闭合曲线。
   - 打开**颤音**（Key_2 长按 0.8 s 切表情档）或**延迟**：图形开始"游走"，是实时的。
4. **读图**：横向摆动幅度 = 左声道电平，纵向 = 右声道电平；图形越"胖"，说明左右内容差异越大。
5. 再按一次 Key_2 回到波形页；断电后回到波形页。

## 8. 答辩口径

> "李萨如页不是贴图，也不是预录。每帧在**行消隐**期间把 512 个立体声采样点
> 按左声道分列、右声道分行，压成一张 512×16 的按列纵向拉幅表（1 块 BSRAM），
> 有效区只做线段绘制。整个更新 3584 个时钟，消隐期有 88200 个时钟，余量 24 倍。"

被追问"为什么单音只是一条线"时：

> "因为左右声道是同一个混音信号按声像系数缩放，数学上必然共线——真实的模拟 X-Y
> 示波器接单声道源也是这条线。要让图形张开必须是左右内容不同，所以和弦、颤音、
> 延迟打开后就能看到闭合曲线。这也正是我们给 8 个声部做声像分布的原因。"

## 9. 已知限制

| 限制 | 说明 |
|---|---|
| 重叠分支被填充成实心带 | span 表只存 ymin/ymax，同一列的多段会被连成一段（模拟示波器同样如此） |
| 单音图形退化 | 左右同源，表现为斜线/窄椭圆；需和弦或加效果才张开 |
| 缩放固定 | `>>> 6`，小音量时图形很小；未做自动增益（频谱页有 AGC，这页没有） |
| 无网格/刻度 | 只有一条中心十字线（x=240, y=96） |
| 与频谱页共用同一块显示区 | 两页不能同屏 |
